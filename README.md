# Naver Writer

[Daewooki/naver-bc-automation](https://github.com/Daewooki/naver-bc-automation)을 기반으로 만든 로컬 네이버 블로그 작성 도구입니다.

상품 등록 → 정보 수집 → AI 초안 생성 → 내용·이미지 검토 → 즉시 발행 또는 예약 순서로 사용합니다. 생성과 발행을 분리하여, 검토한 초안 버전을 그대로 발행합니다.

## 시작

Node.js 20.9 이상이 필요합니다. 이 환경에서는 Node 25.6.1로 검사했습니다.

```sh
npm ci
npm run setup
```

`.env`에 AI_PROVIDER, 해당 공급자 API 키, NAVER_BLOG_ID를 입력합니다. API 키는 채팅이나 Git에 공유하지 않습니다. SQLite 기본값은 `DATABASE_URL="file:./dev.db"`입니다. `OPENAI_MODEL`과 `GEMINI_MODEL`로 모델을 변경할 수 있습니다.

```sh
npm run login   # 열린 브라우저에서 직접 로그인
npm run dev     # http://127.0.0.1:3000
```

별도 터미널에서 작업 실행기를 켭니다.

```sh
npm run worker
```

화면에서 AI 연결 확인, 로그인 상태 확인을 사용할 수 있습니다. AI 연결 확인은 모델 조회만 하며 글을 생성하지 않습니다. 실제 생성 권한·한도는 초안 생성 요청에서 확인됩니다.

## 사용 흐름

1. 상품 링크와 참고 메모를 등록합니다.
2. 상품 정보 수집을 실행해 상품명·가격·이미지를 확인합니다.
3. AI 초안 생성으로 제목·본문·태그를 준비합니다. 이 단계는 공급자 API를 호출합니다.
4. 초안을 수정하고 사용할 이미지를 선택합니다. 저장 후 검토 완료로 표시합니다.
5. 즉시 발행 또는 한국 시간으로 예약합니다. 실제 블로그 게시 동작입니다.
6. 결과 확인 필요 상태라면 블로그를 직접 확인하고 게시물 URL 또는 미게시 여부를 기록합니다.

수집을 다시 하면 기존 검토 상태가 해제됩니다. 원본 상품이 바뀌었을 수 있으므로 초안도 확인하거나 다시 생성하세요. 이미 발행된 상품은 중복 발행하지 않습니다. 작업 이력이 있는 링크는 기록 보존을 위해 삭제하지 않습니다.

예약은 Mac이 깨어 있고 워커가 실행 중일 때만 처리됩니다. 5분 이상 지난 예약은 자동 발행하지 않고 확인 대기로 전환합니다. 시간을 바꾸려면 예약을 취소하고 새 시간을 등록합니다. 실행 중 취소는 최종 발행 클릭 이전의 안전한 단계에서 처리됩니다.

## 신뢰성과 제한

- SQLite 큐와 단일 워커 잠금, 작업별 로그, 중복 실행 제약을 사용합니다.
- API 키·쿠키는 API 응답과 작업 로그에 포함하지 않습니다.
- 로그인은 편집기 접근 확인 후 저장하며, 세션 상태 캐시는 5분입니다.
- 게시 버튼 클릭만으로 성공 처리하지 않습니다. 대상 블로그의 글 URL과 제목을 확인합니다. 확실하지 않으면 자동 재발행하지 않습니다.
- 상품 데이터는 JSON-LD와 메타 태그 및 DOM에서 수집합니다. 접근 차단이나 네이버 편집기 변경이 있으면 중단될 수 있습니다.
- 실제 구매·사용 경험을 만들어내도록 지시하지 않으며, 제휴 안내와 구매 링크를 본문 끝에 추가합니다.
- 로컬 단일 사용자용입니다. 공개 서비스용 계정·인증 기능은 없습니다.
- 실계정 로그인 및 실제 상품·게시 검증은 별도입니다. 자동 테스트는 외부 AI·네이버 게시를 실행하지 않습니다.

기존 GUIDE.md는 상류 저장소의 이전 사용 설명입니다. 현재 사용 방법은 이 README를 기준으로 합니다.

## 검증

```sh
npm test
# 대시보드가 실행 중일 때:
npm run test:browser
npm run lint
npx tsc --noEmit
npx tsc --noEmit --project tsconfig.scripts.json
npm run build
npm audit
```

핵심 테스트는 임시 SQLite DB에 마이그레이션을 재생합니다. 브라우저 테스트는 가짜 상품 페이지 및 API 응답을 사용합니다.

## DB 변경

`prisma/migrations`가 변경 이력입니다. 기존 DB는 초기 전환 전에 `prisma/backups`에 백업했습니다. 새 설치는 `npm run setup`으로 생성하고, 기존 설치 업데이트는 백업 후 `npm run db:migrate`를 실행합니다. `db push` 대신 migration을 사용해야 DB의 중복 작업 방지 인덱스를 유지할 수 있습니다.
